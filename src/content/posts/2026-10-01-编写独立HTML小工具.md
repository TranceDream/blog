Labs 用来放可以直接使用的小工具。每个工具是独立的原生网页，博客只负责列表、展示外壳和共用样式，工具内部的逻辑留在自己的目录中。

当前健康计算器与 JSON 工具都采用这种结构。新增工具无需编写专属 Astro 页面，也不需要维护工具注册表。

## 新建工具目录

在 `src/content/labs/<id>/` 下创建文件，目录名使用简短的小写英文和连字符，例如 `my-tool`：

```text
src/content/labs/my-tool/
├── index.md       # 必需：元数据与可选的补充说明
├── index.html     # 必需：完整 HTML 文档
├── style.css      # 可选：工具自己的布局
├── client.js      # 可选：浏览器交互
├── core.js        # 可选：独立计算逻辑
└── core.test.js   # 可选：逻辑测试，不公开输出
```

工具目录直接放在 `labs/` 下；当前集合只扫描 `*/index.md`。这与文章的 `YYYY-MM-DD-标题.md` 命名不同：工具目录名直接决定访问地址，发布后尽量保持稳定。

## 填写工具元数据

`index.md` 的内容例如：

```yaml
---
title: My Tool
description: 一句话介绍工具
publishedAt: 2026-10-01T00:00:00+08:00
status: finished # finished | experiment
tags: []
---
```

三个必填字段是 `title`、`description` 和 `publishedAt`。`status` 默认是 `finished`，标签默认是空数组。需要补充操作说明时，可以在 frontmatter 后继续写 Markdown，内容会显示在工具下方。

Labs 元数据没有文章的 `type`、`presentation` 或 `draft` 字段；`experiment` 只是展示状态，并不会隐藏工具。尚未准备好公开的工具应暂时保存在内容目录之外。

## 编写原生网页

`index.html` 使用完整 HTML 文档，并保留 `<head>`，博客会在这里注入共享样式与主题桥接脚本：

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My Tool</title>
  <link rel="stylesheet" href="./style.css">
</head>
<body>
  <main>
    <p>一个独立的小工具。</p>
    <button type="button" id="run">运行</button>
    <p id="result" role="status"></p>
  </main>
  <script type="module" src="./client.js"></script>
</body>
</html>
```

`client.js` 可以直接使用浏览器 API：

```js
const button = document.querySelector('#run');
const result = document.querySelector('#result');
button.addEventListener('click', () => {
  result.textContent = '工具已经运行。';
});
```

JavaScript 使用浏览器能直接运行的语法。资源按原样输出，不经过 TypeScript 或 npm 依赖打包；模块间使用 `./core.js` 这样的相对导入，不能直接导入裸包名。复杂工具可以先自行构建，再把浏览器可运行的产物放入工具目录。

## 跟随博客样式

博客自动注入 `src/features/labs/shared.css`，提供字体、基础排版、表单控件和统一滚动条。工具自己的 CSS 写布局即可，例如：

```css
main { max-width: 48rem; margin-inline: auto; }
#result { color: var(--accent); }
```

颜色优先使用 `--bg`、`--text`、`--accent`、`--surface`、`--muted` 和 `--line`，避免写死浅色或深色。共享 CSS 先加载，工具的 `style.css` 后加载，可以按需覆盖。

在博客展示页中，iframe 会跟随博客主题，内容高度变化也会更新外层 iframe 高度。避免为根容器设置依赖 iframe 高度的 `100vh` 布局；让内容自然撑开即可。

iframe 隔离了工具与博客的 CSS。它没有安全沙箱，脚本拥有同源访问能力，因此这里适合经过审核的自有工具。数据处理尽量在浏览器内完成；若需要上传，应明确告诉使用者。

## 访问地址与资源

新增目录后，博客自动生成两个入口：

- `/labs/my-tool/`：带博客页头、介绍和页脚的展示页。
- `/lab-artifacts/my-tool/index.html`：独立网页，通过 HTTP 单独打开时使用共享样式的默认深色主题。

独立打开不会同步博客主题，也不需要 iframe 高度调整。不要把通过站点打开与双击源文件混为一谈：源文件本身没有被注入共享 CSS，浏览器模块也应通过 HTTP 访问。

图片、脚本和样式使用相对路径。资源扩展名清单位于 `src/features/labs/asset-types.ts`；目前支持 HTML、CSS、JS、JSON、SVG、PNG、JPG/JPEG、WebP、GIF、WASM 和 WOFF2。需要其他格式时先扩展清单，再验证输出。

Markdown、隐藏文件以及文件名包含 `.test.` 的资源不会公开输出。其余允许类型的文件可能被发布，因此不要把私有配置放在工具目录中。

## 本地验证

在博客根目录执行：

```sh
npm run check
git diff --check
npm run build
npm run astro -- dev --background
```

打开 Labs 列表进入工具，再检查独立网页、深浅主题、手机宽度，以及内容展开后是否被截断。新增或删除目录后如开发服务器没有刷新路由，可重启开发服务；正式构建会重新扫描目录。

现有工具的逻辑测试可以这样运行：

```sh
node --test src/content/labs/*/core.test.js
```

整个 Labs 由 `src/config/site.ts` 中的 `SITE.features.labs` 控制。关闭后不会生成 Labs 页面与资源；重新开启即可恢复。`npm run build` 只生成本地静态文件和搜索索引，不会自动部署。
