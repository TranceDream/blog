一篇交互式文章应该首先是一篇能独立阅读的文章。展示区负责让抽象变化变得可见，但不应该迫使作者维护另一套平行结构。

现在的写法只保留一个通用的 `InteractiveArticle`。正文、图片、代码和控件全部写在同一个 `.mdx` 文件里；页面外层只负责布局和切换。

> 最重要的原则是：正文表达完整结论，展示负责验证结论。即使 JavaScript 没有运行，读者仍然可以读完文章并看到第一个展示。

## 先把内容拆成少量阶段

开始写页面之前，先列出读者真正需要经历的认知阶段。一个阶段只回答一个问题，并产生一种可以观察的变化。

例如，要解释“队列如何工作”，四个阶段已经足够：准备输入、加入队列、取出项目、得到结果。这里描述的是叙事阶段，而不是动画帧。

## 新建一个组合式 MDX 文件

在 `src/content/posts/` 中新建 `YYYY-MM-DD-标题.mdx` 文件，例如 `2026-10-01-队列如何工作.mdx`。同名时在扩展名前追加 `-1`、`-2`，不要覆盖已有文章。只有需要组合式展示的 Tech 文章才使用这种格式；Life、Notes 和普通 Tech 文章继续写 Markdown。

最小 frontmatter 如下：

```yaml
---
type: tech
title: 队列如何工作
description: 观察数据进入和离开队列的过程。
publishedAt: 2026-10-01T00:00:00+08:00
draft: true
tags: [data-structure, interaction]
presentation: composed
toc: true
---
```

`presentation: composed` 会启用组合布局；没有这个字段时，文章使用普通阅读布局。文章路由已经注入 `InteractiveArticle`，无需自行导入它。

`draft: true` 会同时隐藏本地与构建后的列表、详情页、搜索和 RSS。准备在本地预览时明确改为 `false`；这个字段不是部署开关。

## 在正文旁边写展示内容

整篇内容放进一个 `<InteractiveArticle>`。每个 H2 后面可以就近写一个带有 `slot="display"` 的原生 `section`：

```mdx
<InteractiveArticle>

## 准备输入

先准备三个等待处理的项目。

<section slot="display" data-stage-panel data-label="输入">

**初始队列**

`A → B → C`

</section>

## 加入队列

新项目总是进入队尾。

<section slot="display" data-stage-panel data-label="入队">

`A → B → C → D`

</section>

</InteractiveArticle>
```

Astro 会把这些 `section` 按源码顺序放进右侧展示区，其他内容仍留在正文列。步骤名称直接读取对应 H2，所以不需要再维护标题数组。

标题太长时，可以只给对应 `section` 增加 `data-label="输入"` 作为短标签；不写则自动使用 H2。

这里保留几个简单约束：

- H2 数量和展示 `section` 数量保持一致。
- 两者按顺序一一对应；补充层级使用 H3。
- `section` 必须是 `InteractiveArticle` 的直接子节点，并在标签与 Markdown 之间保留空行。
- 正文 H2 不要套在其他容器内；展示面板中避免 H2/H3，以免混入文章目录。

<section slot="display" data-stage-panel data-label="章节">

```text
H2 01  ─────→  display 01
H2 02  ─────→  display 02
H2 03  ─────→  display 03
```

<p>标题既是正文结构，也是展示步骤名称。</p>

</section>

## 展示区可以放什么

展示 `section` 接收正常的 MDX 子内容，因此可以直接放 Markdown、代码块、图片、视频、SVG、表单、原生控件或显式导入的 Astro 组件。

下面这个展示里就包含真实的浏览器控件。调整滑杆、展开详情，再切换到其他阶段后返回；它们的状态不会被重新创建。

如果某块内容拥有复杂脚本，再把**那一小块**抽成 Astro 组件并在 MDX 顶部导入。普通 HTML 控件可以直接使用，但计算或动画逻辑需要自己实现；当前项目没有安装 React 等客户端框架，使用 island 前需要先配置对应集成。

完整 HTML 工具可以按 Labs 的目录规范单独维护，再用 iframe 引用。文章中的 iframe 不会自动获得 Labs 外壳的主题同步和高度调整；需要明确设置尺寸，并按内容需要配置 `sandbox`。

不建议在 MDX 里写会污染全站的裸全局样式，也不要把“任意内容”理解成任意执行不受约束的脚本。

## 为什么切换可以保持无缝

所有展示面板都会在首次生成页面时进入 DOM，并重叠在同一个 CSS Grid 区域。切换只改变当前面板的可见状态，不替换 HTML，也不重新挂载组件。

因此切换本身不会重置输入值、`details` 展开状态或重新挂载组件；Canvas、iframe 等仍由各自脚本管理。隐藏面板不会自动暂停视频或后台任务，需要时由工具自行处理。面板之间只使用很短的透明度过渡；减少动态效果模式下则立即切换。

为了避免视觉跳动，展示舞台保持稳定高度，较长内容在面板内部滚动。图片、视频和 iframe 应声明尺寸或 `aspect-ratio`，避免资源加载后撑开布局。

宽于 `60rem` 时，正文与展示各占一半宽度，展示固定在视口侧边，滚动正文会同步步骤；桌面端不显示步骤按钮。`60rem` 及以下，展示区放在正文上方，停止滚动同步并显示手动步骤按钮。按钮支持左右方向键、Home 和 End。

展示区进入和离开视口时，深色背景与内容会平滑显隐。正文沿用全站主题，展示内容优先使用 `--stage-text`、`--stage-muted` 和 `--stage-accent`，确保在深色背景上可读。

## 在本地完成验收

写完后先执行静态检查和本地构建：

```sh
pnpm check
git diff --check
pnpm build
```

将待预览文章设为 `draft: false` 后，启动后台开发服务器：

```sh
pnpm astro dev --background
```

从 Archive 打开文章，详情地址由内容 ID 生成：`/archive/<id>/`。通常来自去掉扩展名的文件名，其中英文字母会转为小写，最终地址以 Archive 列表链接为准。不要手填 `slug` 或 `layout` 字段。发布前至少确认：

- [ ] 文件扩展名是 `.mdx`，并设置了 `presentation: composed`。
- [ ] 每个正文 H2 都有一个对应展示面板。
- [ ] 桌面端滚动正文能切换对应展示，窄屏端可直接选择首末步骤。
- [ ] 切回表单、图片或交互组件时，内部状态仍然保留。
- [ ] 键盘方向键、Home、End 和焦点状态正常。
- [ ] 手机端只手动切换，正文脱离展示后仍然完整。
- [ ] 图片与嵌入内容声明了稳定尺寸。
- [ ] 正文使用全站主题变量，展示内容在深色舞台上清晰可读。
